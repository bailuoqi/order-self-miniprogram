# 客户端电脑网页适配规划书

一期在现有 `mini-program/` uni-app 客户前端上做电脑浏览器适配：新增宽屏顶栏导航壳、隐藏宽屏下的底部 Tab、全站内容居中限宽，并对发布需求、订单详情、聊天三类核心页做宽屏布局，使客户能在电脑上走通「浏览服务 → 发布需求 → 看报价 → 聊天商议 → 确认 → 付定金（模拟）→ 看交付 → 付尾款（模拟）→ 评价 → 加入我们」全流程。一期不另建独立 PC 站、不改 `admin/` 后台布局、不改 `server/` 接口契约、不恢复抢单与师傅入驻、不做品牌官网与 SEO。电脑端登录一期沿用现有 H5 体验登录、支付一期沿用现有模拟支付，正式扫码登录与微信 Native 扫码支付放二期。预计一期总工作量约 13–15 人天，可拆成 4–5 个并行工作流，单流最长约 3.5 人天。

---

## 1. 策略结论

采用「uni-app H5 电脑适配」：一套 `mini-program/` 代码同时编译微信小程序（`npm run dev:mp-weixin`）、手机 H5 与电脑 H5（`npm run dev:h5`，http://localhost:8081），不拆独立 PC 站，不引入新前端仓库。

一期策略（按投入产出排序）：

| 层次 | 做法 | 覆盖范围 |
| --- | --- | --- |
| 公共壳 | `pages.json` 增加 H5 专属 `topWindow` 顶栏（`matchMedia.minWidth: 768`）；宽屏下隐藏底部 tabBar；全局内容最大宽度 1200px 居中 | 全部页面 |
| 重点宽屏页 | 发布需求/提交需求表单居中窄栏、订单详情双栏、聊天室居中加宽 | `subpkg/order/create-custom`、`subpkg/order/create`、`subpkg/order/detail`、`subpkg/chat/room` |
| 其余页 | 仅加媒体查询：居中限宽、卡片栅格化、底部固定条限宽 | 首页、分类、服务列表/详情、订单列表、消息、支付、评价、我的、加入我们、设置/关于/退款 |
| 演示打底 | 登录沿用 H5 体验登录（`/auth/dev-login`），支付沿用模拟支付（`/payment/mock`），页面上明确标注演示性质 | 登录、支付 |

## 2. 信息架构

- 底部 Tab 处理：桌面宽度（≥768px）改为顶栏导航，隐藏 uni-app H5 渲染的底部 tabBar；手机 H5 与微信小程序保持现状四 Tab（首页/消息/订单/我的）不变。`pages.json` 的 `tabBar` 配置本身不删不改。
- 顶栏（H5 宽屏专属，新增 `mini-program/windows/top-window.vue`）：左侧品牌名「定制接单」，中间导航项——首页、服务分类、标准服务、发布需求、我的订单、消息，右侧头像/登录入口（点击进「我的」）。当前 Tab 高亮，跳转复用 `uni.switchTab` / `uni.navigateTo`。
- 全局导航规则：Tab 四页由顶栏直达；子包页（分类、服务列表/详情、下单、订单详情、聊天、支付、评价、加入我们等）保留 uni-app 自带页头返回，顶栏在这些页上依旧可见，保证电脑上任何页都能一键回首页。
- 内容最大宽度：常规页 1200px 居中；表单类页（发布需求、提交需求、评价、加入我们）内容列 760px；聊天室 960px；支付页 560px。页面背景色铺满全宽，仅内容列限宽。
- 一期不做面包屑、不做侧栏、不做页脚，顶栏不显示未读角标（见「需确认」）。

## 3. 断点与单位

断点定义（以浏览器视口宽度计）：

| 档位 | 范围 | 行为 |
| --- | --- | --- |
| 手机 | <768px | 完全维持现状：底部 Tab、rpx 布局、窄屏卡片 |
| 小桌面/平板 | 768–1199px | 顶栏出现、tabBar 隐藏、内容居中限宽、卡片开始栅格化（2 列） |
| 大桌面 | ≥1200px | 订单详情双栏、服务列表 3 列、首页热门服务改栅格 |

验收核对宽度取 375 / 1366 / 1920 三档，1366 与 1920 共用 ≥1200 档样式，靠 max-width 居中兜底，不为 1920 单设断点。断点数值与 uni-app `topWindow.matchMedia.minWidth: 768` 默认习惯对齐。

rpx 与 px 分工，核心原则是「旧样式不动，新样式分层」：

1. 既有 rpx 样式（字号、卡片内间距、圆角、图标尺寸）全部保留不改，微信小程序包因此零样式变化。
2. uni-app H5 对 rpx 有换算上限：在 `manifest.json` 新增 `h5` 节点显式声明 `rpxCalcMaxDeviceWidth: 960`、`rpxCalcBaseDeviceWidth: 375`（即当前默认值），锁定桌面上 rpx 按 375 基准换算（28rpx≈14px），保证桌面字号可读且行为不随框架升级漂移。`h5` 节点仅 H5 生效，不进 `mp-weixin` 包。
3. 新增的桌面布局代码（max-width、栅格列宽、顶栏高度、双栏间距）一律用 px，写在 `@media (min-width: 768px)` / `@media (min-width: 1200px)` 内。
4. 凡引用 H5 内部选择器（如 `.uni-tabbar`）或 `document`/`window` 的样式与脚本，必须再包一层 `/* #ifdef H5 */`（样式）或 `// #ifdef H5`（脚本），双保险确保不进小程序包。
5. 断点值以 SCSS 变量收敛到新增的 `mini-program/common/responsive.scss`，各页只引用变量，不散写魔法数字。

## 4. 逐页方案

### 4.1 首页 `pages/index/index.vue`

电脑布局：

```
[topWindow 顶栏]
[hero 横幅 + 快捷入口(同一行，各占约 60%/40%)]  ≤1200px 居中
[公告条]
[软件定制分类栅格] [电子代做分类栅格]
[热门标准服务：≥1200px 改 4 列卡片栅格；768–1199px 保持横向滚动]
[客户评价：3 列卡片]
```

与小程序差异：小程序保留自定义导航栏（搜索框+头像）与横向滚动热门区；桌面宽屏下隐藏页内自定义导航栏（其职责由顶栏承担），热门区由 `scroll-view` 横滚改为栅格铺开（CSS 控制，不改数据逻辑）。现有 H5 滚轮横滚补丁与滚动条样式（已用 `#ifdef H5` 包裹）保留，供 768–1199px 档使用。

风险：自定义导航栏用 `statusBarHeight` 内联样式，隐藏时要连 sticky 占位一起处理，避免顶部留白；`category-item` 固定 `width: 20%`，宽屏下图标间距过大，需在媒体查询里改列数而不是改结构。

### 4.2 服务分类 `subpkg/category/index.vue`

电脑布局：左侧分类栏加宽至 220px，右侧服务列表 ≥1200px 时 2 列卡片；整体 1200px 居中。该页已用 `calc(100vh - var(--window-top))` 计算高度，topWindow 出现后 `--window-top` 由框架自动更新，天然兼容。

与小程序差异：仅列数与栏宽不同。风险：双 `scroll-view` 嵌套在桌面滚轮体验一般，一期接受，不改结构。

### 4.3 标准服务列表 `subpkg/product/list.vue`

电脑布局：筛选栏（综合/销量/价格/评分）居中限宽 1200px；服务条目 768–1199px 双列、≥1200px 三列卡片栅格。

与小程序差异：小程序单列纵向列表不变；桌面为多列，卡片内部结构（封面 200rpx 图 + 标题 + 价格 + 按钮）不动。风险：多列后 `text-ellipsis-2` 截断高度不齐导致卡片高低不平，用 CSS grid 拉伸对齐规避。

### 4.4 服务详情 `subpkg/product/detail.vue`

电脑布局：

```
[左栏 46%：封面大图]   [右栏 54%：价格卡+下单流程卡]
[服务说明（通栏）]
[客户评价（通栏）]
[底部操作条：限宽 1200px 居中]
```

与小程序差异：封面现为 `width: 750rpx`（桌面上折算约 375px 偏小），媒体查询内改为百分比宽；底部固定操作栏在桌面限宽居中并保留「客服 + 提交需求」按钮。风险：`margin: -24rpx` 的价格卡叠压效果在双栏下取消，需单独处理；改动全部走媒体查询，避免影响小程序。

### 4.5 发布需求 `subpkg/order/create-custom.vue`（含标准服务下单 `subpkg/order/create.vue`）

电脑布局：流程提示条 + 表单卡居中 760px；品类选择弹窗由「底部抽屉」改为「居中模态」（仅媒体查询改定位，不改逻辑）；附件区、合规提示随表单列走；底部提交条限宽 760px 与表单对齐。

与小程序差异：小程序保持底部抽屉与全宽提交条；表单字段、校验（品类/标题/描述/联系方式/工期必填）、`uni.chooseImage` 上传逻辑完全一致。风险：附件上传只支持图片（`chooseImage`），电脑用户常有 pdf/zip 需求，一期不改（见第 10 章与二期）；`textarea` 在桌面需给更高的 `min-height`，避免大屏上输入区过矮。

### 4.6 订单列表 `pages/order/list.vue`

电脑布局：状态 Tab（全部/待报价/待付定金/制作中/待付尾款/待评价/已完成）居中限宽 1200px；订单卡片单列但加宽，操作按钮随卡片右对齐。

与小程序差异：仅限宽与留白。风险：页面用 `height: 100vh` + `scroll-view` 自滚，桌面下滚动条出现在内层，观感可接受，一期不改结构；`scrolltolower` 加载更多在桌面滚轮下已验证可触发（uni-app H5 支持），验收时列入检查。

### 4.7 订单详情 `subpkg/order/detail.vue`

电脑布局（≥1200px 双栏，CSS grid 区域重排，不改 DOM 顺序）：

```
[状态横幅（通栏，限宽 1200px）]
[左栏 62%]                    [右栏 38%]
  需求信息                       团队报价卡（含报价历史）
  交付成果                       操作区（联系团队/确认报价/付定金/付尾款/去评价/取消/退款）
  我的评价                       订单进度时间线
  订单信息
```

与小程序差异：小程序保持单列卡片流 + 底部固定操作条；桌面把底部操作条改为右栏内的操作卡（同一组按钮，媒体查询切换定位方式）。风险：本页是全站最复杂页面，双栏用 `grid-template-areas` 给现有卡片指定区域即可，若个别卡片条件渲染（如未报价、未交付）导致区域空缺，grid 自动收缩，需在 1366px 下重点走查；操作按钮种类随状态变化多，右栏操作卡要覆盖全部 10 种状态组合。

### 4.8 聊天（报价商议）`subpkg/chat/room.vue`

电脑布局：整页居中 960px；顶部订单条、消息列表、输入条同宽；消息气泡 `max-width` 从 480rpx 放宽到约 60% 列宽；输入条固定在限宽容器底部，Enter 发送（现有 `confirm-type="send"` 在 H5 即回车触发，验收确认即可）。

与小程序差异：小程序全宽不变；5 秒轮询拉取消息机制两端一致，一期不上 WebSocket。风险：`scrollTop = messages.length * 200` 的估算滚底在桌面高消息列表下可能滚不到底，属现有问题，一期在验收中观察、必要时微调估算系数（不改接口）；图片消息 `uni.previewImage` 在桌面为移动风格弹层，可用但不美观，一期接受。

### 4.9 支付 `subpkg/order/pay.vue`

电脑布局：金额卡 + 支付方式卡 + 按钮区整体居中 560px，视觉重心突出金额。「模拟支付成功（开发演示）」按钮保留并在桌面加「演示环境」角标文案；「支付定金/尾款」正式按钮在 H5 点击维持现有提示弹窗（引导用模拟支付）。

与小程序差异：小程序走 `uni.requestPayment` 微信支付，不变；H5 一期只有模拟支付可用。风险：演示按钮误上生产造成真实订单被标记已付，上线前必须由后端在生产环境禁用 `/payment/mock`（与 `/auth/dev-login` 同策略），列入二期上线清单。

### 4.10 消息列表 `pages/message/message.vue`

电脑布局：会话列表居中 960px，行高与头像微调。与小程序差异：仅限宽。风险：低。

### 4.11 我的 `pages/my/index.vue`

电脑布局：头部用户卡+订单统计限宽 1200px；「服务」四宫格与「其他」列表改为两列排布。与小程序差异：小程序保留曲面渐变头部与微信一键登录按钮；H5 显示「体验登录」按钮（现有条件编译已区分）。风险：头部 `header-bg` 用 `transform: scaleX(1.5)` 画弧形，宽屏下弧度失真，媒体查询内改为平底渐变条。

### 4.12 加入我们 `subpkg/my/join-us.vue`

电脑布局：介绍卡 + 申请表单居中 760px，申请状态卡同宽；提交条与表单对齐。与小程序差异：仅限宽；姓名/联系方式/方向/简介/作品/附件字段与审核状态展示逻辑不变。风险：低；附件同样受「仅图片」限制，随 4.5 一并在二期增强。

### 4.13 其余页（设置/关于/退款记录）

`subpkg/my/settings.vue`、`subpkg/my/about.vue`、`subpkg/my/refund-list.vue` 统一居中 760px，无结构改动，随「沟通与其他」工作流顺带完成。

## 5. 条件编译原则

| 手段 | 适用场景 | 本项目实例 |
| --- | --- | --- |
| `// #ifdef H5`（脚本） | 依赖 `document`/`window`/DOM 事件、H5 专属 API 调用、宽屏 JS 逻辑 | 首页滚轮横滚补丁（已有）；App.vue 中按 `matchMedia('(min-width:768px)')` 调 `uni.hideTabBar()/showTabBar()` 的监听 |
| `/* #ifdef H5 */`（样式） | 引用 H5 内部选择器或仅桌面需要的大段样式 | 隐藏 `.uni-tabbar` 的规则；首页 scroll-view 滚动条样式（已有） |
| CSS `@media` | 纯宽度驱动的布局差异：限宽、栅格列数、双栏、底部条定位 | 各页 `@media (min-width: 768px)` / `(min-width: 1200px)` 块；建议同时包 `/* #ifdef H5 */` 以减小小程序包体 |
| H5 专属配置键 | 只对 H5 编译生效的配置 | `pages.json` 的 `topWindow`；`manifest.json` 的 `h5` 节点 |

绝不能进 `mp-weixin` 包的内容：`windows/top-window.vue` 及其引用（仅被 `topWindow` 配置加载，天然隔离）；一切 `.uni-*` 选择器样式；`document/window/navigator` 访问；`vue-router` 直接引用。反向约束：小程序专属能力（`open-type="getPhoneNumber"`、`uni.requestPayment` 微信支付分支）保持在 `#ifndef H5` / `#ifdef MP-WEIXIN` 内，现状已符合。

新增代码自查口径：改动只允许出现在「媒体查询块、`#ifdef H5` 块、H5 专属配置键、新增 windows/common 文件」四类位置；`npm run build:mp-weixin` 产物对比无差异即为合规。

## 6. 登录与支付

| 项目 | 一期（电脑演示） | 二期（正式上线） |
| --- | --- | --- |
| 登录 | 沿用体验登录：`App.vue` H5 启动自动调 `/auth/dev-login`，「我的」页保留「体验登录」按钮；页面加「演示账号」标识 | 推荐微信扫码登录：申请微信开放平台「网站应用」，顶栏/我的页出二维码，回调 code 由 server 新增 `/auth/wx-qr-login` 换取 unionid 并与小程序账号打通；备选手机号+短信验证码登录（需短信通道） |
| 定金支付 | 沿用 `/payment/mock` 模拟支付，按钮文案明示「演示」 | 推荐微信 Native 支付：PC 页面展示付款二维码，手机微信扫码支付，前端轮询订单状态，复用现有 `/payment/wxpay/notify` 回调；`/payment/wxpay` 增加 `trade_type` 字段（属"体验缺口必须补字段"的允许范围） |
| 尾款支付 | 同上，模拟支付 | 同上，Native 扫码；手机浏览器（非微信内）访问 H5 时用微信 H5 支付（MWEB），微信内置浏览器访问时用 JSAPI（需公众号网页授权） |

推荐项已写死如上，不留空。配套要求：二期上线时生产环境必须禁用 `/auth/dev-login` 与 `/payment/mock`（后端注释已声明 dev-login 生产禁用，上线清单中逐项复核）。

需确认：`mini-program/api/request.js` 的 `BASE_URL` 与 `subpkg/order/detail.vue` 的 `SERVER_ORIGIN` 目前硬编码 `http://localhost:3001`。推荐一期维持现状仅供本地/内网演示，二期部署时改为同域反向代理 `/api`（Nginx 已在仓库内有配置基础），避免跨域与混合内容问题。

## 8. 验收标准

三档宽度：电脑 1366、电脑 1920、手机 375（Chrome 设备模拟 + 真机微信小程序）。下列流程必须全部走通：

| # | 流程 | 1366 | 1920 | 375（H5+小程序） |
| --- | --- | --- | --- | --- |

| 3 | 服务详情 → 提交需求（含图片附件上传）→ 跳转订单详情 | 必须 | 必须 | 必须 |

| 5 | 订单列表按状态 Tab 筛选、滚动加载更多、进详情 | 必须 | 必须 | 必须 |
| 6 | 订单详情 → 联系团队 → 聊天发送文本（桌面 Enter 发送）、查看图片消息 | 必须 | 必须 | 必须 |

## 9. 分期

一期（本规划书范围，最小可用电脑体验）：第 1–8 章全部内容——公共壳、13 个页面宽屏适配、体验登录与模拟支付打底、三档宽度验收。

二期（一期验收后启动）：微信开放平台扫码登录与账号打通；Native 扫码支付（PC）与 H5/JSAPI 支付（手机浏览器）；上传增强（pdf/zip 附件、拖拽上传）；聊天升级（会话列表+聊天室双栏、WebSocket 替代轮询）；`BASE_URL` 环境化与同域部署；H5 history 路由与基础分享标题。

明确不做（两期都不做）：独立 React/Vue PC 站；`admin/` 后台布局改造；抢单、师傅认证、师傅入驻的任何恢复；品牌官网、SEO 营销站、多语言、暗色模式；小程序端任何视觉或流程变更。

## 10. 风险

| 风险 | 影响 | 规避办法 |
| --- | --- | --- |
| 底部固定条（详情/表单/支付/评价/加入我们共 6 处 `position: fixed` 条）在宽屏横贯全屏 | 观感差、遮挡内容 | 媒体查询内统一限宽居中（`left:50% + translateX(-50%) + max-width`），订单详情改为右栏操作卡；小程序样式不动 |
| `scroll-view` 在桌面的滚轮/滚动条体验 | 横向区域滚不动、无滚动条提示 | 首页已有 `#ifdef H5` 滚轮补丁与滚动条样式，推广该模式；≥1200px 横滚区改栅格铺开，绕开问题 |
| rpx 换算导致固定宽元素在桌面偏小（如 750rpx 封面） | 图片/横幅显示过窄 | `manifest.json` 锁定 rpx 换算参数；对固定 rpx 宽的少数元素在媒体查询内改百分比/px |
| 宽屏隐藏 tabBar 与 topWindow 显隐的窗口 resize 竞态 | 拖拽窗口时出现双导航或无导航 | CSS 媒体查询为主、`uni.hideTabBar()` 为辅双保险；验收含动态拖拽用例 |
| 文件上传仅 `uni.chooseImage`（图片） | 电脑用户无法传 pdf/zip 需求文档 | 一期文案引导「文档类资料可在聊天中说明或留链接」；二期用 `#ifdef H5` 接 `uni.chooseFile` 增强，不动小程序 |
| 电脑无法调起微信 JSAPI 支付 | 正式支付流程在 PC 断链 | 一期模拟支付明示演示性质；二期上 Native 扫码支付（第 6 章方案） |
| `/auth/dev-login`、`/payment/mock` 演示接口误入生产 | 资损与脏数据 | 上线清单强制项：生产环境禁用两接口并回归验证 |
| 自定义导航页（首页/我的）与顶栏叠加 | 双头部、顶部留白 | 宽屏下隐藏页内自定义导航，其搜索/头像入口移交顶栏；`--window-top` 由框架维护，分类页高度计算自动正确 |
| `uni.showModal`/`previewImage`/`showToast` 桌面观感为移动风格 | 交互略显廉价 | 一期接受（能办事优先），不自研弹窗组件，避免包体与回归成本 |
| 聊天滚底估算（`messages.length * 200`）在桌面失准 | 新消息不自动滚到底 | 验收观察，必要时仅调估算系数；结构性修复留二期 WebSocket 改造一并做 |
| 媒体查询误伤小程序包 | 小程序包体增大或样式异常 | 桌面样式统一加 `/* #ifdef H5 */`；以 `build:mp-weixin` 产物 diff 为准的机械自查 |
