# 客户端电脑网页适配规划书 — 提示词

把下面全文交给负责出规划书的 AI。要求只出规划，不要改代码。

---

你是资深产品经理 + 前端架构师。请只输出一份《客户端电脑网页适配规划书》，不要改代码、不要写大段实现、不要另起仓库。

## 已定前提（不要再讨论、不要推翻）

1. 不另写独立电脑网站，不把客户前端重写成单独的 React/Vue PC 项目。
2. 在现有 uni-app 客户前端上做电脑浏览器适配：一套代码同时编微信小程序、手机 H5、电脑 H5。
3. `admin/` 管理后台已经是电脑网站，本次不改布局。
4. 客户业务是团队接单，不是抢单平台。流程固定为：

   客户下单 → 报价商议 → 敲定订单 → 合约+付定金 → 交付成果+付尾款 → 客户评价

5. 小程序/H5 只有客户角色。没有抢单、没有师傅认证。团队成员只在后台添加。可保留「加入我们」。

## 项目事实

路径：`D:\wxxcx\order-self-miniprogram`

- `mini-program/`：uni-app Vue3，H5 开发地址 http://localhost:8081
- `admin/`：Vue 后台 http://localhost:5173
- `server/`：NestJS，小程序和 H5 共用；本次不改接口契约，除非某个体验缺口必须补字段

现状：客户 H5 按手机写（rpx、底部 Tab、窄屏卡片），几乎没有桌面媒体查询。电脑能打开，但像被拉宽的手机页。

- 登录：小程序微信一键登录；H5 目前是体验登录。
- 支付：小程序微信支付；H5 目前用模拟支付提示。

## 规划目标

电脑浏览器要能舒服完成：浏览服务、发布需求、看报价、聊天商议、确认、付定金、看交付、付尾款、评价、加入我们。

一期以「能办事」为准，不是品牌官网、不是 SEO 营销站。

## 规划书必须包含的章节

按这个顺序写，章节标题不要用问句。

1. **策略结论**  
   用陈述句写死：采用「uni-app H5 电脑适配」，不拆独立 PC 站。  
   写清一期策略（例如：公共壳限宽/顶栏；发需求、订单详情、聊天做宽屏；其余页居中限宽）和工作量（人天）。

2. **信息架构**  
   电脑上如何处理底部 Tab（改为顶栏或侧栏）、全局导航、内容最大宽度。

3. **断点与单位**  
   手机 / 平板 / 桌面的宽度断点；rpx 与 px 如何分工，才能不把微信小程序包弄坏。

4. **逐页方案**  
   至少覆盖：首页、标准服务列表/详情、发布需求、订单列表/详情、聊天、支付、我的、加入我们。  
   每页写：电脑布局（文字结构图）、和小程序差异、风险。

5. **条件编译原则**  
   哪些用 `#ifdef H5`，哪些用 CSS media，哪些绝不能进 `mp-weixin`。

6. **登录与支付**  
   电脑浏览器一期演示方案、二期上线方案（登录、定金、尾款），直接给推荐项，不要留空。

7. **改造清单**  
   预计会动 `mini-program` 哪些目录/公共布局；明确不动 `admin`、不改抢单逻辑。

8. **验收标准**  
   电脑 1366、1920 和手机 375 下，必须能走通的流程清单。

9. **分期**  
   一期最小可用电脑体验、二期再做的事、明确不做的事。

10. **风险**  
    uni-app H5 在 PC 上的底栏、滚动、文件上传、支付等已知坑，以及规避办法。

## 约束

- 不要把「要不要独立写电脑站」写成待选项或问句。
- 不要恢复抢单、师傅入驻。
- 不要输出代码补丁；需要示意时最多 10 行伪代码或结构描述。
- 用中文，标题+列表+表格，篇幅以一次能读完为准。
- 不确定处标注「需确认」，并给出你的推荐项（仍用陈述句）。

## 输出格式

开头用不超过 5 句陈述「一期做什么、不做什么、预计工作量」。  
然后按上面 10 章展开。  
文末附「给开发 AI 的任务拆条」，每条一句话，可当后续开发附录。
