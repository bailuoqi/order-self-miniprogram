## 1. 策略结论

- **一期七个 PR（#12–#18）已顺序合并进 master（合并提交、无冲突、未 force-push），二期直接基于 master 施工。** 七个分支共同基点为原 master tip，且文件所有权两两无交集，合并零冲突；合并后 `cd admin && npm run build` 通过。master tip：`ff534b3`。
- **客户端消费走「全量替换 + 兜底」策略。** 客户端首页拿到合法的 `schemaVersion:1` 配置（≥1 个可渲染且非空的组件）时，内容区完全按配置渲染（真所见即所得）；配置缺失/旧形状/为空/请求失败时，**渲染现有硬编码首页原样兜底**，守住演示质量。不做「配置与硬编码混排」的中间态——那会让"改了没生效"的老问题换个形式回来。
- **schema 以本文档第 5 章为唯一权威契约。** 一期已把编辑器 payload 固化为 `{schemaVersion:1, components:[{_id,type,props}], global}`，二期不改形状、只补消费语义（单位、图标白名单、不消费字段）。C1（客户端）与 C3（编辑器）各自持有实现，以本章为准对齐，无跨端共享代码（Vue web 与 uni-app 无法共包）。
- **服务端只做加法。** 保留既有 `GET/PUT /page-config/:key` 契约不变（编辑器与客户端在 C2 未合入时照常工作）；新增 publish/revisions/rollback/meta 四个端点补齐草稿→发布的服务端语义与回滚能力。
- **营销组件（优惠券/倒计时/拼团/秒杀）从组件库下架。** 产品定位是团队定制接单（先报价后开工），无优惠券/秒杀业务模型，补后端模块没有价值；一期的「无数据支撑」角标是过渡，二期直接从库里移除，存量数据不删（画布显示「已停用」占位、客户端跳过），杜绝伪装可用。
- **客户端改动限定在首页消费链路。** 一期冻结的 H5 桌面适配成果不动；本期只动 `pages/index/index.vue` 的内容区渲染与新增渲染器组件，桌面宽屏（topWindow、限宽、栅格）规则原样继承。

## 5. schemaVersion:1 契约（唯一权威）

### 5.1 顶层形状

```json
{
  "schemaVersion": 1,
  "components": [ { "_id": "c_xxx", "type": "banner", "props": { } } ],
  "global": {
    "pageTitle": "首页", "bgColor": "#f5f6fa",
    "navStyle": "default | search | none",
    "navBgColor": "#ffffff", "navTextColor": "#333333",
    "showTabbar": true, "tabItems": []
  }
}
```

存储：`PUT /page-config/:key` body 为 `{ config: <上述对象> }`；读取端（编辑器与客户端）都必须做三形状嗅探（新规范 / 直接对象 / 旧 `{data:"json"}` 双重 JSON），嗅探失败视为「无配置」。

### 5.2 客户端渲染子集（10 类）与消费规则

| type | 关键 props | 客户端渲染 | 空值/跳过规则 |
|---|---|---|---|
| banner | `images:string[]`、`height`(px)、`interval`(ms)、`dots`、`radius` | swiper 轮播，autoplay 按 interval | images 为空 → 整块跳过 |
| search | `placeholder`、`bgColor`、`radius` | 搜索条，点击进分类/服务检索页 | `hotWords` 不消费 |
| notice | `text`、`ico`、`bgColor`、`color` | 公告条，单行省略 | text 为空 → 跳过；`speed` 不消费（不做跑马灯） |
| navGrid | `items:[{icon,name,link}]`、`columns`、`gutter` | 宫格导航，图标走白名单（5.4） | items 为空 → 跳过 |
| titleBar | `title`、`subtitle`、`moreText`、`moreLink`、`align` | 区块标题栏 | title 为空 → 跳过 |
| imageAd | `src`、`link`、`height`(px)、`radius` | 图片广告，点击走链接解析 | src 为空 → 跳过；`width` 不消费（恒 100%） |
| goodsRow | `title`、`goods:[{id,title,price,cover}]`、`layout:scroll\|grid`、`columns`、`showBadge` | 服务卡片（横滚/栅格），点击进服务详情 | goods 为空 → 跳过；**price 单位为分，显示需 ÷100** |
| richText | `content`(html)、`padding`(px) | H5 用 v-html、小程序用 rich-text | content 为空 → 跳过；管理员输入、后台已鉴权，客户端不再拼接进 URL/脚本上下文 |
| divider | `height`、`color`、`margin`、`style` | 分割线 | 恒渲染 |
| blank | `height`(px)、`bgColor` | 占位块 | 恒渲染 |

**统一规则**：

- **未知/子集外 type 静默跳过**（coupon/countdown/groupBuy/seckill/videoPlayer/articleList/floatingBtn 及未来新增类型），保证前向兼容。
- **尺寸换算**：props 中数值型 px 均以 375 宽画板为基准，客户端换算 `rpx = px × 2`（uni-app `rpxCalcBaseDeviceWidth:375`，≥768 桌面宽屏下 rpx 不再随视口缩放，与画布一致）。
- **global 消费**：`pageTitle/navBgColor/navTextColor/navStyle` 作用于移动端页内自定义导航栏；`bgColor` 作用于页面背景。**H5 宽屏（≥768px）导航由 topWindow 顶栏承担，页内导航整体隐藏（继承一期规则），global 导航项在宽屏不生效**。`showTabbar/tabItems` 不消费——真实 tabBar 由 `pages.json` 决定，编辑器画布内仅为示意（C3 需在属性面板标注）。
- **合法配置判定**：`schemaVersion === 1` 且 `components` 为数组且**至少 1 个属于子集且非空跳过**的组件；不满足即走硬编码兜底。

### 5.3 链接解析（navGrid.link / imageAd.link / titleBar.moreLink / notice.link）

- 空字符串 → 不可点击。
- `/pages/...` → tabBar 页（index/order/message/my 四个）用 `uni.switchTab`，其余 `uni.navigateTo`。
- `/subpkg/...` → `uni.navigateTo`。
- `http(s)://` → H5 直接跳转；小程序端复制链接并 toast「链接已复制」（无 web-view 载体页）。
- 解析失败静默忽略，不抛错。

### 5.4 图标白名单

客户端 `remixicon.woff2` 是**完整字体**（仅 CSS 类被裁剪为 76 个），因此扩白名单只需在 `remixicon-trimmed.css` **追加类→码点映射**，零字体体积成本。二期白名单 = 既有 76 类 + C1 追加以下 10 类（覆盖编辑器默认值与常用导航语义）：

`ri-service-line`、`ri-calendar-line`、`ri-star-line`、`ri-more-line`、`ri-volume-up-line`、`ri-image-line`、`ri-search-line`、`ri-apps-line`、`ri-shopping-bag-3-line`、`ri-gift-line`

- C1：渲染器遇白名单外图标回退 `ri-apps-2-line`。
- C3：navGrid/notice 图标输入从自由文本改为白名单选择器（builder 内自持常量副本 `client-icons.js`，以本节为准）；存量配置中白名单外图标显示警告标。

## 6. 逐项方案

### 6.1 客户端消费 page-config（C1，闭环 D1/E1）

- **渲染器**：新建 `mini-program/components/page-config/config-blocks.vue`（或按块拆分的同目录组件组）+ 纯函数模块 `mini-program/common/page-config.js`（形状嗅探 sniff、合法性判定、px→rpx、价格格式化、链接解析、图标白名单回退——均为无平台差异纯函数，双端可编译）。
- **接入点**：`pages/index/index.vue` 内容区二选一渲染：合法配置 → `<config-blocks :components :global>`；否则 → 现有硬编码区块原样。顶部导航 chrome（品牌/搜索/头像）常驻不受配置影响（移动端配色吃 global，宽屏隐藏交给 topWindow，均继承现状）。
- **加载策略**：`onShow` 拉 `GET /page-config/home`（公开接口，无需登录）；成功且合法则渲染并写入 `uni.setStorageSync('home_page_config')`；下次启动先用缓存首帧直出再后台刷新；失败/不合法清缓存走兜底。配置请求与既有 fetchData 并行，互不阻塞。
- **草稿预览**：H5 且 URL query 含 `preview=draft` 时改拉 `home-draft`，页面角标「草稿预览」，不写缓存——团队在电脑浏览器即可验收未发布效果（`home-draft` 的 GET 本就公开，无新增暴露面）。
- **桌面宽屏**：配置版内容区继承一期 H5 桌面规则（限宽 1200 居中、≥768 隐藏页内导航）；goodsRow 在 ≥1200 桌面下 scroll 布局自动转 4 列栅格（与一期热门服务的处理一致），banner/imageAd 恒通栏限宽。
- **品牌名消费（E7）**：读 `GET /page-config/settings` 的 `brand_name` 应用于首页导航与 `windows/top-window.vue` 顶栏，失败回退「定制接单」。

### 6.2 服务端 page-config 增强（C2，闭环 E2）

全部为**加法**，既有 GET/PUT 契约与行为不变：

- `POST /page-config/:key/publish`（AdminAuthGuard）：body 可带 `{config}`（先写 `:key-draft` 再落 `:key`，一次调用完成保存+发布）或不带（把 `:key-draft` 现存内容复制到 `:key`）；维护两行 status（draft 行 `draft`、发布行 `published`）；每次发布写入一条 revision。
- 新实体 `page_config_revisions`：`{id, page_key, config_json, action('publish'|'rollback'), operator, created_at}`；TypeORM `synchronize:true` 自动建表（SQLite/MySQL 均适用），每 key 仅保留最近 20 条，超出裁剪。
- `GET /page-config/:key/revisions`（AdminAuthGuard）：倒序返回 `{id, action, operator, created_at, summary}`（summary 为组件数等轻量摘要，不回整包 json）；`GET /page-config/:key/revisions/:id` 返回完整 config 供预检。
- `POST /page-config/:key/rollback`（AdminAuthGuard）：body `{revisionId}`，把该版本写回 `:key` 与 `:key-draft` 并记一条 `rollback` revision。
- `GET /page-config/:key/meta`（AdminAuthGuard）：返回 `{page_key, status, updated_at}`，编辑器显示「最后保存时间」，也为三期乐观锁备好数据面。
- `PUT /page-config/:key` 追加体积护栏：`config_json` 超 200KB 返回 400（防把图片 base64 误存进配置）。
- 注意 Nest 路由顺序：新端点均为两段路径（`:key/publish` 等），与既有单段 `:pageKey` 不冲突；`GET /page-config`（getAllKeys）保持在参数路由之前的现有声明顺序。

### 6.3 编辑器打磨与预览一致性（C3，闭环 E3/E4/E5）

- **发布链路升级**：发布优先调 `POST /page-config/home/publish`（带当前 config，一次完成保存+发布）；接口 404/失败时回退现有双 PUT（与 C2 并行安全，任意合并顺序可用）。信息条从「暂未接通（二期接通）」改为「已接通：发布后客户端首页按本配置渲染；标注为不渲染的组件会被客户端跳过」。发布成功提示附「复制客户端草稿预览地址」入口（`/#/?preview=draft` 相对路径 + 域名说明）。
- **发布历史与回滚**：工具栏「历史」按钮开抽屉，列 `GET /page-config/home/revisions`（时间/操作人/摘要），每条带「回滚到此版本」（确认弹窗 → rollback → 重载画布并重打首帧快照）；revisions 接口不可用时入口整体隐藏。
- **「客户端不渲染」角标体系**：videoPlayer/articleList/floatingBtn 在库面板与画布组件上加灰色「客户端不渲染」角标（替代一期「二期接通」话术）；richText 保留（子集内）。
- **图标白名单选择器**：见 5.4；`client-icons.js` 落在 `admin/src/components/builder/`（C3 自有目录，不跨流 import）。
- **预览一致性修复（W5）**：CompRenderer 与 ProductPicker 的商品价格按分→元格式化显示；global 面板的 showTabbar/tabItems 标注「仅画布示意，客户端 tabBar 固定」；imageAd 的 width 属性从面板移除（客户端恒 100%）；notice 标注「客户端为单行省略展示」。

### 6.4 营销组件去留（决策：下架）

- 组件库移除「营销」tab（coupon/countdown/groupBuy/seckill 不可再添加）。
- 存量配置中的营销组件**不删数据**：画布渲染为灰色「已停用组件（客户端不渲染）」占位，可选中删除，不可编辑属性；发布 payload 原样保留（客户端按未知类型跳过，无害）。
- 模板库中含营销组件的模板同步清理该组件。

### 6.5 设置/权限遗留盘点

一期已闭环：设置服务器化（`page-config/settings`：brand_name/deposit_ratio/service_phone）、报价定金预填读设置、路由 meta.role 与侧栏角色过滤、editor 直连受限 URL 重定向。二期仅补一件事：**客户端消费 brand_name**（E7，归 C1）。角色粒度细化、乐观锁等不在本期。

### 6.6 后台 UI 收敛（C4，闭环 E6）

- 将一期各流的 scoped 确认弹窗/toast/分页迁移到 S1 全局组件：`ui/AppConfirm`（Orders 无/OrderDetail/Refunds/Recruits/Products/Categories/Cms/Admins 的确认与理由必填弹窗）、`ui/AppToast`（各页保存/失败提示）、`ui/AppPagination`（Orders/Users 分页条）。迁移原则：**行为与文案不变，纯替换实现**；理由必填类弹窗若 AppConfirm 不支持输入框，则扩展 AppConfirm 增加可选输入插槽（C4 拥有 ui/* 所有权）。
- PageBuilder 内部弹窗**不在本期收敛范围**（避免与 C3 文件冲突，三期再并）。
- 收尾核查：`git grep -E "alert\(|confirm\(|prompt\(" admin/src/views` 全站零残留；删除各 view 中已无引用的 scoped 弹窗样式与死代码。

## 7. 验收标准

1. **端到端闭环（核心）**：编辑器拖入 banner（上传真图）/navGrid/notice/titleBar/goodsRow（选真实服务）→ 发布 → 客户端 H5 首页（375 宽与 ≥1200 桌面宽各验一遍）按配置顺序渲染，商品价格显示元、点击进对应服务详情、navGrid 图标正常显示且链接可跳转；仅保存草稿不发布时客户端无变化；`?preview=draft` 可见草稿并带角标。
2. **兜底**：`page-config/home` 为旧形状/空 components/接口失败三种情况下，客户端首页渲染既有硬编码版式，控制台无未捕获错误。
3. **一致性**：同一份发布配置逐组件核对画布与客户端——类型、顺序、文案、图片、价格（元）、列数/布局一致；客户端跳过的组件在画布上均带「客户端不渲染/已停用」标注。
4. **服务端**：publish 一次调用完成保存+发布并产生 revision；revisions 列表倒序、每 key ≤20 条；rollback 后 `GET /page-config/home` 与 `home-draft` 均为目标版本且新增 rollback 记录；超 200KB 的 PUT 返回 400；既有 GET/PUT 行为回归不变。
5. **编辑器**：营销 tab 消失、存量营销组件显示停用占位且可删除；图标选择器只出白名单；C2 未部署时发布仍可用（回退双 PUT）、历史入口隐藏。
6. **UI 收敛**：改造过的后台页面弹窗/toast/分页视觉统一为 ui/* 组件，`git grep` 原生弹窗零残留。
7. **工程**：`admin` 与 `server` 构建通过；`mini-program` H5 构建通过且渲染器代码不含裸用的 H5-only API（H5 专属逻辑在 `#ifdef H5` 内）；全路由走查控制台无未捕获错误。

## 8. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 客户端首帧闪烁（兜底→配置切换） | 观感 | 本地缓存配置首帧直出；无缓存时兜底与配置区块同骨架背景，切换无布局跳动 |
| goodsRow 快照过期（服务改价/下架后配置仍存旧快照） | 信息偏差 | 快照仅作展示、点击进详情看实时数据；编辑器 ProductPicker 重选即刷新；实时合并放三期 |
| 富文本 v-html 进入客户端 | XSS 面 | 内容仅后台管理员可写（PUT 有 AdminAuthGuard）；客户端仅渲染不拼接；小程序端 rich-text 本身不执行脚本 |
| revisions 表膨胀 | 存储 | 每 key 保留 20 条自动裁剪；summary 列表不回整包 json |
| C3 发布升级与 C2 端点并行合并顺序不定 | 功能降级 | C3 全部新调用做 404 容错回退（发布回退双 PUT、历史入口隐藏），与一期跨流容错同款纪律 |
| 图标白名单与 trimmed.css 追加不同步 | 图标缺失 | 白名单以本文档 5.4 为唯一清单；C1 渲染器对白名单外统一回退 `ri-apps-2-line` |
| 双端编译（渲染器误用 DOM API） | 小程序端编译失败 | 渲染器规定只用 uni 组件与纯函数；H5 专属包 `#ifdef H5`；验收含 H5 构建 |
| 营销组件下架引起演示落差 | 演示话术 | 存量占位说明「产品定位无此业务模型」；模板同步清理，不再出现在新画布 |

## 9. 给开发 AI 的任务拆条（4 个并行工作流）

**通用纪律**：只改本流「文件所有权」列出的文件；不跨流 import 对方新建组件；新增依赖为零；对未合入的兄弟流接口一律容错（404 隐藏/回退）；交付前本流构建通过（admin→`npm run build`；server→`npm run build`；mini-program→H5 构建）并按第 7 章对应条目自验；分支独立开 PR。schema 一切以第 5 章为准。

### C1 客户端首页渲染（mini-program）
**文件所有权**：`mini-program/pages/index/index.vue`、新建 `mini-program/components/page-config/*`、新建 `mini-program/common/page-config.js`、`mini-program/static/fonts/remixicon-trimmed.css`（仅追加）、`mini-program/windows/top-window.vue`

- **U1 配置获取与判定**：`common/page-config.js` 实现三形状嗅探、合法性判定（5.2）、px→rpx、分→元、链接解析（5.3）、图标白名单回退（5.4）；`onShow` 拉取 + storage 缓存首帧 + 失败清缓存兜底。
- **U2 区块渲染器**：`components/page-config/*` 实现 10 类子集组件（banner=swiper、search、notice、navGrid、titleBar、imageAd、goodsRow scroll/grid、richText、divider、blank），未知类型与空组件跳过；样式对齐画布视觉（间距/圆角/阴影与现有首页卡片风格统一）。
- **U3 首页接入与兜底**：`pages/index/index.vue` 内容区按合法性二选一渲染；导航 chrome 常驻并吃 global 配色；硬编码版式完整保留为兜底分支；配置请求与既有数据请求并行。
- **U4 桌面宽屏与草稿预览**：配置版内容区继承限宽/隐藏页内导航规则；goodsRow ≥1200 桌面 scroll 转 4 列栅格；H5 `?preview=draft` 读 home-draft + 角标 + 不写缓存。
- **U5 图标补齐**：`remixicon-trimmed.css` 追加 5.4 的 10 个类映射（码点对照 remixicon 官方表；字体文件不动）。
- **U6 品牌名消费**：首页导航与 top-window 品牌名读 `page-config/settings` 的 brand_name，失败回退「定制接单」。

### C2 服务端 page-config 通道（server）
**文件所有权**：`server/src/modules/page-config/*`（controller/service/module/entity + 新建 revision entity）

- **V1 publish 端点**：`POST /page-config/:key/publish`（AdminAuthGuard），带 config 则先写 `:key-draft` 再落 `:key`，不带则复制 draft→published；维护 status；写 revision。
- **V2 发布历史**：`page_config_revisions` 实体（synchronize 自动建表）；`GET /:key/revisions` 轻量摘要倒序 + `GET /:key/revisions/:id` 全量；每 key 保留 20 条自动裁剪。
- **V3 回滚**：`POST /:key/rollback`（body `{revisionId}`）写回 `:key` 与 `:key-draft` 并记 rollback revision。
- **V4 meta 与护栏**：`GET /:key/meta` 返回 `{page_key,status,updated_at}`；PUT 超 200KB 返回 400；既有 GET/PUT 契约与 DEFAULT_CONFIGS 行为不变（回归自验）。

### C3 编辑器发布链路与一致性（admin builder）
**文件所有权**：`admin/src/views/PageBuilder.vue`、`admin/src/components/CompRenderer.vue`、`admin/src/components/PropsEditor.vue`、`admin/src/components/builder/*`（含新建 `client-icons.js`、`RevisionDrawer.vue`）

- **W1 营销组件下架**：库移除营销 tab；存量实例画布渲染「已停用组件（客户端不渲染）」灰色占位（可选中删除、不可编辑属性）；模板清理营销组件；payload 不删存量数据。
- **W2 发布升级与文案**：发布优先 `POST /page-config/home/publish`（带 config），404/失败回退双 PUT；信息条改「已接通」文案；发布成功提供「复制客户端草稿预览地址」。
- **W3 发布历史抽屉**：RevisionDrawer 列 revisions（时间/操作人/摘要）+ 回滚（确认弹窗→rollback→重载画布重打首帧快照）；接口不可用整体隐藏。
- **W4 图标白名单选择器**：navGrid item 与 notice ico 改白名单网格选择器（`client-icons.js` 常量副本，以 5.4 为准）；存量白名单外图标加警告标。
- **W5 预览一致性**：CompRenderer/ProductPicker 价格分→元显示；videoPlayer/articleList/floatingBtn 加「客户端不渲染」角标；global tabbar 面板标注「仅示意」；imageAd width 属性移除；notice 标注单行省略。

### C4 后台 UI 收敛（admin 非 builder）
**文件所有权**：`admin/src/components/ui/*`、`admin/src/views/*.vue`（**除** PageBuilder.vue）、`admin/src/assets/style.css`（仅追加）

- **X1 AppConfirm 收敛**：扩展 AppConfirm 支持可选「理由输入（必填校验）」插槽；OrderDetail 取消原因、Refunds 审核、Recruits 通过/拒绝、Products 上下架、Categories/Cms/Admins 删除确认全部迁移；行为与文案不变。
- **X2 AppToast 收敛**：各页 scoped 保存/失败提示迁移 AppToast（全局单例挂 Layout 或组合式封装，由 C4 决定并写明用法注释）。
- **X3 AppPagination 收敛**：Orders/Users 的 scoped 分页条迁移 AppPagination，交互参数（页码/total 展示）不变。
- **X4 死代码清理与核查**：删除已无引用的 scoped 弹窗样式；`git grep -E "alert\(|confirm\(|prompt\("` 全站零残留；全路由走查无控制台错误。

### 并行安全性说明

四流文件集合两两无交集（C1=mini-program、C2=server、C3=admin builder 四文件+builder 目录、C4=admin 其余视图+ui+style.css）。跨流仅存运行时容错依赖：C3 调 C2 新端点（404 回退/隐藏）、C1 读 `page-config/home`（数据由既有 PUT 产生，不依赖 C2 合入）、C1 与 C3 通过本文档第 5 章对齐 schema 与白名单（无代码共享）。任意合并顺序均可独立构建、独立验收。
