# 后台管理系统电脑网页适配施工方案

在现有 `admin/`（Vue 3 + Vite 手写 CSS 后台）上原地增强，不另起新后台。目标是让团队成员在 1366×768 与 1920×1080 的电脑浏览器上舒适走通「工作台 → 订单报价 → 沟通 → 交付 → 收款审核」主流程，并把**首页可视化装修（页面装修/PageBuilder）**从一个存在多处硬伤的演示编辑器打磨成可靠好用的编辑器。一期零后端接口改动（全部复用既有 API，包括通用的 `PUT /page-config/:key` 与 `POST /upload/image`），不碰 `mini-program/` 客户端。全部工作拆成 **6 个文件互不重叠的并行工作流（S1–S6，任务 T1–T24）**，可由多个开发 AI 同时施工。

---

## 1. 策略结论

- **在现有 admin Vue 上增强，不另起后台。** `admin/` 已是标准 Vite + Vue 3 桌面 SPA（16 个视图 + 2 个组件，共约 2600 行），信息架构完整、API 层可用，问题集中在宽屏布局、交互质感（大量 `alert/confirm/prompt`）、功能断头（装修配置无人消费、商品封面字段未暴露、设置只存 localStorage）。推倒重来毫无必要。
- **不引入 UI 框架（Element Plus 等）。** 现有页面全部基于 `assets/style.css` 的手写类（`.card/.table/.btn/.tag/.form-*`），引入框架等于全量重写且与既有风格割裂。一期继续走「全局工具类 + 页面内 scoped 样式」路线。
- **一期零 server 契约改动。** 审计确认所需能力后端均已具备：订单列表支持 `keyword/source/status/page/pageSize`；`PUT /page-config/:key` 对任意 key 通用（可承载草稿 key 与设置 key）；`POST /upload/image`、`POST /upload/file` 可用；商品实体已有 `cover/images` 字段。
- **页面装修的「客户端不消费」硬伤如实标注、二期接通。** 小程序/H5 首页（`mini-program/pages/index/index.vue`）完全不读取 `page-config`，首页是硬编码的分类/热门/公告/评价。一期不改客户端（其 H5 桌面适配刚完成、明确冻结），编辑器内做诚实标注并把 schema 固化，二期由独立工作流接通。
- **屏幕基线：1366×768 必须可用，1920×1080 必须舒适**；内容区限宽居中防止表格拉满 1900px；低于 1280 不做承诺（后台不做移动端适配）。

## 3. 信息架构与布局原则

- **壳层 = 深色侧栏(230px) + 新增浅色顶栏(56px) + 内容区**。侧栏保留现有分组导航，按角色过滤条目（D14）；顶栏放当前页标题（取路由 meta.title）、未读消息铃铛（聚合 `/chat/admin/sessions` 的 team_unread，30s 轮询）、当前登录人（显示名+角色 tag）与退出入口。1440px 以下侧栏可折叠为 64px 图标栏（localStorage 记忆）。
- **内容区限宽**：`max-width:1600px; margin:0 auto; padding:24px`。1920 下表格不再满幅；1366 下等效于现状全宽。全站最低支持宽度 1280，更窄时容器出横向滚动而非布局崩坏。
- **编辑器类页面全屏接管**：页面装修改为 `position:fixed; inset:0` 全屏覆盖 + 工具栏「返回后台」按钮（解 D2 且不依赖 Layout 改动，利于并行施工）。
- **双栏原则**：详情/编辑类页面在 ≥1366 用 `grid-template-columns: minmax(0,1fr) 侧栏定宽` 双栏（订单详情=信息+聊天、CMS 编辑=源码+预览、商品编辑=表单+图片区），侧栏 `position:sticky` 不随长内容折行。
- **交互质感**：新增全局 Toast 与确认弹窗组件替代 `alert/confirm`；`prompt` 一律改为带表单校验的页内弹窗（沿用 Categories.vue 的 `.modal-mask/.modal-box` 既有范式）。**并行安全约定：一期各工作流在自有 .vue 文件内实现 scoped 弹窗，不跨流 import 新组件**；全局组件仅由 S1 落地并用于 S1 自有文件，二期统一收敛。
- **样式纪律**：`assets/style.css` 只允许 S1 追加类，禁止改名/删除既有类；其他工作流的新样式一律写在自己 .vue 的 scoped 块中。断点仅用两个：`@media (max-width:1440px)`、`@media (max-width:1366px)`。
- **空态统一**：沿用 `.empty` 类（图标+文案+可选动作按钮），所有列表页补齐。

## 5. 首页编辑器专项

### 5.1 定位与最大的坑
编辑器本体（撤销/重做、四类 17 种组件、模板、全局设置、快捷键）骨架完整，但 **D1 是首要事实：装修结果目前没有任何端在渲染**。一期策略：不改客户端（冻结），把编辑器自身做扎实、把 schema 固化成唯一权威（`{schemaVersion:1, components:[{_id,type,props}], global:{...}}`），编辑器顶部常驻信息条「装修配置暂未接通客户端首页展示（二期接通）」，杜绝"改了没生效"的误解。二期由独立工作流让 `mini-program` 首页按此 schema 渲染基础组件子集。

### 5.2 布局（1366 / 1920）
- **全屏接管**：`position:fixed; inset:0; z-index:100`，顶部 50px 工具栏新增左侧「← 返回后台」；解 D2 双滚动条且零 Layout 依赖。
- **三栏**：左组件库 240px（1920 下 260px、库项三列网格）、中画布自适应居中、右属性面板 300px（1920 下 320px）。
- **1366×768**：垂直空间紧张，画布默认「适应高度」缩放（phone 高约 700px 需缩到 ~0.85）；面板内部各自滚动，工具栏与面板头固定。
- **1920×1080**：画布 100% 原尺寸居中，两侧留白由画布区背景填充；可选 125% 放大精修。

### 5.3 画布
- 保留 375px 手机框（消费端是小程序/H5，手机画布是正确的所见即所得基准；桌面 H5 客户端渲染差异大，桌面预览不做，避免给出失真承诺）。
- 缩放控制：75% / 100% / 125% / 适应高度，`transform:scale` 实现，缩放中心顶部对齐。
- **插入指定位置**（解 D6）：库拖拽 dataTransfer 用 `lib:<type>` 前缀、排序用 `sort:<idx>` 前缀区分；dragover 时按鼠标在目标组件上/下半区显示蓝色插入指示线，drop 按指示位置 splice 插入；拖到空白区仍追加末尾。

### 5.7 保存与发布（解 D3/D4/D5/D9）
- **通道分离**：草稿写 `PUT /page-config/home-draft`，发布把当前内容写 `PUT /page-config/home`（通用 pageKey 接口，零后端改动）；进入编辑器优先载 `home-draft`，无则载 `home`；工具栏显示「草稿未发布」状态徽标。

### 5.8 已知坑清单（施工时勿踩）
1. D1：别顺手去改 mini-program 首页"接通渲染"——客户端冻结，接通是二期独立决策。
